Core ideas

The ideas every decision is checked against. Most came out of our brainstorms, and several were measured.

Large, high-quality work from small models running on your own Mac, and nowhere else.

The harness's job is to squeeze the model to its limit through directed refinement. Random retries ("monkeys at typewriters") are not the method.
01

Local, and only local

No cloud model, no fallback, no bring-your-own-key, no hosted tier, even where local can't match frontier quality.

Gaps are closed with local levers: harness reliability, renderers, MoE models, effort limits, local tool channels, LoRA on the Mac.
02

Prompt pressure is a finished fix

The system is non-deterministic. A well-aimed prompt that moves the odds beats task-specific machinery that narrows what the harness can do.

Hard rules are reserved for the harness's own honesty: refuse unparseable writes, refuse commands that never return, keep paths in the workspace, report what is true.
03

Aim at the moment of action

Measured on the 4B: a guideline line in the system prompt changed nothing. The same point made in a tool's result, at the moment of the call, worked.

"Don't do X" goes in the tool's answer. The system prompt only says which tool to reach for. Re-run the same task to see whether a line moved the model.
04

Every role is an agent with tools

Never a bare completion. Running bare, qwen overthinks: about 15,400-token turns, against about 1,300 inside a harness.

The agent mesh: any role can talk to any peer. Robustness checks (import graph, verify) become tools that agents call, not gates.
05

Per-step reliability is the lever

A 30-step task where each step succeeds 95% of the time finishes 21% of the time. At 99% per step it finishes 74% of the time.

Long tasks are won by making each step dependable: catch loops, recover empty replies, keep files true.
06

The corporation shape

A hierarchy that grows with the task: the CEO holds the vision, managers write contracts, engineers build, specialists review.

Scope sets the depth, memory sets the width, effort sets how much review. The hierarchy only runs at the top two efforts.
07

CLI over MCP, code over screenshots

Models are trained on bash and --help. In bash-CLI mode the prompt prefix is 1,770 tokens instead of 8,185.

Every connector is a command. Blender and Godot are driven through code, not by clicking screenshots.
08

The machine comes first

A generation once froze your Mac. Now the guardian admits each job by its real memory footprint, and holds or sheds jobs before the machine suffers.

Low power slows a job down instead of stopping it. Heavy workers run behind the pointer at QoS tiers 5/5.
09

Prefill is the number people feel

The wait for the first token is what makes a chat feel slow or fast. Warming the prompt when a model is selected took turn-1 first token from 2,021 ms to 101 ms.

No chat or harness change is done until its time to first token is logged and every re-prefill fixed.
10

No raw red errors

Every failure is said in plain words with its fix as a button. Where the app can fix it itself, it does.

plainError, turn-problem cards, held sends, amber toasts with actions.
11

Reference-quality UI, Bobble's own language

Teal accent, Fraunces titles, Hugeicons at 1px, grounded shadows. No emoji anywhere. Never a hand-drawn brand logo.

Components are built from reference specs on one shared core, so one fix lands everywhere.
12

Your attention is the scarce resource

You judge only feel and first impressions. Everything an agent can verify, an agent verifies.

Headless by default, reports with images, decisions batched for you below.
13

Keep it modular

Every capability is a part that can be added, swapped or removed without reaching into another. Your words, 2026-10-09.

Engines behind baseUrl, connectors as commands, generation features as modules, engine fixes as start-up patches, the quick panel as its own window, one shared UI core.

Open gaps

What still fails or feels wrong. The reliability gaps matter most to the corp harness.

Reliability gaps (8)

  • A 2B looped for 26 minutes with no identical calls. The loop guard needs a wall-clock "no progress" budget.
  • The 27B's first send waits ~122 s on "starting up".
  • Compaction summarizes nothing on a small window and still costs a model call.
  • "Thought for 1m 28s" shown over ~20 minutes of thinking.
  • The renderer page was replaced mid-turn under swap (10–13% memory free).
  • An inline maths page isn't rebuilt after an app restart.
  • The 4B writes research into notes.md instead of answering (3 of 4 runs).
  • "What time is it" sometimes runs date instead of the connector.

Smaller known bugs (8)

  • The office chip flickers (1 of 15 probe runs).
  • Image-to-image edits come out too subtle.
  • A finished card remounts into the chain when the next tool starts.
  • A picture embedded in a reply shows twice.
  • ⌘Z into a turn that is already answering keeps the partial reply.
  • A message with only a picture can't be rewound.
  • Ladle build in the bundle (excluded, unconfirmed).
  • A short answer in the quick panel sits in a mostly empty panel.

How we work

The standing agreements. All of them are in force.

  • Headless by default. I never take your screen or focus. Probes run unseen.
  • Reproduce, fix, reproduce again, look. Before and after images in every report.
  • Report only when done, with images. No "next step" handed back to you.
  • This summary at the end of every task, plus a STATUS table each time it is updated.
  • Install after milestones. Bobble is quit gracefully, never killed.
  • Prefill logged for every chat or harness change.
  • Your benchmark prompts, word for word. I never invent a brief.
  • No time limit unless you set one.
  • Never touch your settings file or pasteboard from a probe. Never print the HF token.
  • Your open Blender scene is changed only with your OK.
  • A branch is not done until it is on main.
  • No personal details in the repo. "The user" (they), generic paths and hosts, no session traces.
  • Don't stop for "context". Long tasks keep going.
