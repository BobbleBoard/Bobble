## 1. Where this app actually stands

**The dominant defect class in this repo is not bugs. It is reachability.** Capability exists, is registered, is unit-tested, has a settings toggle, and cannot be reached from the running app. `ROADMAP-LATEST.md:9-13` says exactly this about the *previous* wave ("capabilities that existed but could not be reached"). That wave was fixed. The class was not: it reproduced in the newest feature, in the generation stack, in the corp pipeline, in the UI, and in the packaging.

### What is half-built

- **The bash-CLI mode — the headline feature — has zero wiring tests and three integration breaks.** `PI_DESKTOP_TOOL_CLI` appears in no test file anywhere in the repo. The worst break: the CLI *advertises* commands built from `pi.getAllTools()` (`packages/harness/src/index.ts:1506`) but *executes* through `toolRegistry.get(name)` (`:1509`), and `captureRegisteredTools` monkey-patches the harness's own `pi.registerTool` — while pi's loader gives every extension its own api whose `registerTool` writes into that extension's own map (`node_modules/.pnpm/@mariozechner+pi-coding-agent@0.68.1_*/dist/core/extensions/loader.js:131-142`, verified in source). So `web search`, `browser click`, `mac snapshot`, `personal calendar`, `mcp list` and every `media generate` command answer *"not registered in this build."* **The feature built to remove false availability reproduces it one layer down.** `packages/harness/src/tools/tool-registry.ts:20-24` asserts the opposite in prose; two other files in the same package record the measured refutation.
- **Generation is four independent stacks and one of them runs.** gen3d (TRELLIS/retopo/rig/ARDY) is deep and real. ComfyUI — the portable baseline for video, music and SFX — is never wired: `registerGenIpc` is called with no `comfyResolveOrigin` and no `comfyInstall` (`apps/desktop/electron/main.ts:591-599`), stranding ~1,500 lines. A second, entirely separate ComfyUI studio backend is registered in main with zero renderer callers (`apps/desktop/electron/studio/studio-main.ts:70-186`).
- **MLX and Apple-FM share a provider name with llama.cpp and almost no contract.** Neither calls pi's `onPayload`/`onResponse` (`packages/provider-mlx/src/stream.ts:160-166`; `provider-afm/src/stream.ts:177-188`), so the user's sampling overrides, the prose loop detector, intent-bias activation and the corp hang-watchdog are all silently inert on them. Every MLX catalog entry carries `bytes: 0`, so `chooseContextCap` returns 65536 on any machine.
- **The composer "+" menu — the app's only capability surface — is 8 dead rows of 13**, measured by driving the built app. `webSearch` is held in state and never read by `submit()` (`apps/desktop/src/chat/ChatComposer.tsx:317` vs `:545-669`).
- **Effort moves one of the four behaviours the brief named.** `reviewPasses: 0` and `adversarialChecks: false` at *every* level (`packages/harness/src/effort/effort.ts:92-145`, verified); `imageRefinePasses` scales 1→4 and has zero consumers. Only `realVerify`/`verifyFixAttempts` change.

## 4. Where local wins

These are the reasons to choose this over the cloud product. **Opinion throughout on prioritisation; the mechanisms cited are code facts.**

**1. Reproducibility — the brief's actual argument, unshipped.** No cloud provider gives you a seed, a weights hash, the inference build, or notice when the weights change. This app *already* pins the llama.cpp build by tag (`llamacpp-manifest.ts:46-54`), *already* verifies a sha256 on download and discards it (`download.ts:210-214`), and *already* writes a per-model manifest sidecar (`model-store/src/manifest.ts:44-67`). Add `seed` to the sampler (b10603 exposes `-s, --seed`; the server dylib contains a bare `seed` string) and write a per-chat run manifest — model + quant + weights sha + build tag + launch args + full sampler + a hash of the canonical system prompt and tool list. One click: "Reproduce this run." *Do not over-claim:* llama.cpp is not bit-deterministic across batch size or slot count, and this M5's Metal fp32 matmul is ~8e-4. Promise "same seed, same launch, same build, same weights", and say so.

**2. Unattended personal work on data nobody will upload.** The app already has Mail, Messages, Calendar, Contacts and Reminders as first-party connectors (`packages/mac-connectors/src/tool-names.ts:17-40`, always loaded at `extension-dirs.ts:22`) and a headless scheduled-run substrate (`scheduled/scheduled-runner.ts`). A weekday morning brief is a *template*, not a feature. This is structurally impossible in the cloud: it needs Full Disk Access and Automation consent granted to a local signed bundle. And a 4-9B model is plenty for summarising a day's headers. **`messages_send` must never be reachable from an unattended template.**

**3. Full-text search over your own corpus, and later an index.** Sessions are JSONL on your disk, run records too, and via connectors so is your mail. Cloud assistants can only search what you uploaded — and a personal corpus is exactly what people refuse to upload. Stage 1 needs no model at all and reuses bytes already being read. Stage 2 (a tiny embedding model on a second `--embedding` server, plus a `recall` tool) is unbounded overnight work with no per-token bill.

**4. Overnight batches at zero marginal cost.** "Generate 200 candidates overnight, show me the ten best" is a budget decision on any cloud API and a free one here. Cloud image APIs rate-limit; your GPU does not. **Prerequisite, not follow-up:** the gen3d `onDown` lock bug (below) turns an overnight batch into one image and 199 lock errors by morning.

**5. Best-of-N sampling on bounded decisions.** N-fold sampling is N-fold spend in the cloud, which is why nobody offers it. Here it is seconds. The K-slot launcher (`supervisor.ts:266-270`) and constrained decoding (`model-call/call-model.ts:50-58`) already exist — draw K samples for the tool-call fixer and the verify pass and take the majority. **Never on the user's chat turn** (K slots split `-c`), and a 3-way agreement from a 4B gates a retry, it does not license a stronger claim.

**6. Speculatively finish the drafted message while the machine is idle.** Every speculative token is billed in the cloud. Here a discarded completion costs watts on a machine that is idle anyway. The prefill channel, the per-sender AbortController and the abort-on-send already exist (`prefill-main.ts:27-60`). **This is also the repo's worst recurring regression shape** — a background call that doesn't reuse the prefix evicts the single slot. It must own its own slot, be off by default, and be measured with the existing `ttft-slots-probe.mjs`.

**7. Your other machines.** `packages/cluster` already parses `tailscale status`, describes a host and probes peers — and `docs/handoffs/README.md:61-79` already publishes the wire contract three other machines are being told to implement. Answering `GET :8765/cluster/hello` is what turns a library into a product: "which of my machines can run the 27B?" Then offload a *whole subagent task* to a peer by pointing `PI_DESKTOP_UTILITY_BASE_URL` at it — `pi-main.ts:171` already sets that env per spawn, so it is choosing a different string, not building a mechanism. This dissolves the 4B-vs-27B tension the roadmap's #1 blocker rests on.

**8. Arbitrating one pool of physical memory between the OS, the app and the engine.** Nobody else has this problem, and nobody else can solve it for you. llama-server's 8 GiB default prompt cache is not a term in either RAM estimator; `-cram` is inherited rather than chosen; the reuse cliff between 1024 and 1536 MiB is measured and unacted-on (`supervisor.ts:141-175`).

**9. Multi-model residency.** b10603 ships a router: `--models-dir`, `--models-preset`, `--models-max` (default 4, LRU eviction), `--models-autoload`, with `cmd_child_to_router` in the binary. The adapter's `plan()` already produces exactly what a preset *is*. This makes a model switch a request instead of a 105-second stall, and lets the corp hold a 4B while chat holds a 9B. **Verified from `--help` and binary strings only — not run.**
